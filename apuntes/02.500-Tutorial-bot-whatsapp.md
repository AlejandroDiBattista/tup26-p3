# Tutorial: bot de WhatsApp en C# con wacli y Microsoft.Extensions.AI

Este tutorial explica como construir una aplicacion C# simple que escucha mensajes de WhatsApp, consulta un modelo de IA y responde por WhatsApp.

La version final esta en `WhatsAppBot.cs` y fue pensada para ser explicada en clase: un solo archivo, pocas piezas y flujo lineal.

## 1. Objetivo

Queremos construir un bot que haga esto:

1. Mantener WhatsApp sincronizado usando `wacli`.
2. Leer periodicamente los ultimos mensajes de un contacto.
3. Detectar mensajes nuevos.
4. Enviar el texto nuevo a un asistente de IA.
5. Permitir que el asistente lea y escriba archivos.
6. Enviar la respuesta por WhatsApp.
7. Salir solamente cuando el contacto envie `/finalizar`.

La idea central es esta:

```text
WhatsApp -> wacli -> C# -> Microsoft.Extensions.AI -> respuesta -> wacli -> WhatsApp
```

## 2. Arquitectura final

El programa esta dividido en piezas chicas:

| Pieza              | Responsabilidad                             |
| ------------------ | ------------------------------------------- |
| Flujo principal    | Coordina el bot.                            |
| `ClienteWhatsApp`  | Encapsula todos los comandos `wacli`.       |
| `AgenteSecretaria` | Encapsula el cliente de IA y el historial.  |
| `ArchivosAgente`   | Herramientas de archivos para el asistente. |
| `AGENTS.md`        | Prompt del asistente.                       |
| `CONTACTOS.md`     | Archivo que administra el asistente.        |

Esta separacion es importante: el flujo principal no conoce detalles de JSON, procesos externos ni tool calling. Solo llama metodos con nombres claros.

Una convencion del codigo: los identificadores de logica estan en espanol (`RecibirTexto`, `ProcesarMensaje`, `IniciarSincronizacion`), y los metodos asincronicos no llevan el sufijo `Async` porque no existe una version sincronica de cada uno. Los tipos que mapean el JSON de `wacli` conservan sus nombres originales (`WacliStoredMessage`, `InboundMessage`, `CommandResult`).

## 6. Flujo principal

El flujo principal se puede leer como una receta:

```csharp
Process? procesoSincronizacion = null;
try {
    procesoSincronizacion = ClienteWhatsApp.IniciarSincronizacion();

    string promptSistema = await LeerPromptSistema(ArchivoAgentes, PromptPorDefecto);
    AgenteSecretaria asistente = new(claveApi, Modelo, promptSistema);
    DateTimeOffset iniciadoEn = DateTimeOffset.Now;

    Console.WriteLine($"Bot activo para {Contacto}. Envia {ComandoFinalizar} por WhatsApp para detenerlo.");

    while (true) {
        await Task.Delay(IntervaloSondeoMs);

        string? textoEntrante = await ClienteWhatsApp.RecibirTexto(Contacto, iniciadoEn);
        if (string.IsNullOrWhiteSpace(textoEntrante)) { continue; }
        if (EsComandoFinalizar(textoEntrante)) { break; }

        string respuesta = await asistente.ProcesarMensaje(textoEntrante);
        if (string.IsNullOrWhiteSpace(respuesta)) { continue; }

        await ClienteWhatsApp.EnviarTexto(Contacto, respuesta);
    }
} finally {
    ClienteWhatsApp.DetenerSincronizacion(procesoSincronizacion);
}

return 0;
```

En pseudocodigo:

```text
iniciar wacli sync
crear asistente
marcar la hora de arranque

mientras true:
    esperar 2 segundos
    pedir el texto nuevo del contacto
    si no hay texto, seguir esperando
    si el texto contiene /finalizar, salir del bucle
    pedir una respuesta al asistente
    enviar la respuesta por WhatsApp

detener wacli sync
```

Esta es la parte mas importante para explicar en clase. Notar que `RecibirTexto` ya devuelve listo el texto nuevo (o `null` si no hay nada), asi que el bucle queda muy corto: leer, decidir, responder.

## 7. Como se detectan los mensajes nuevos

Cuando el bot arranca, `wacli` ya tiene mensajes guardados en su base local. Si el bot respondiera todo lo que lee, contestaria mensajes viejos.

En vez de recordar identificadores de mensajes, el bot usa dos lineas divisorias:

1. La hora de arranque (`iniciadoEn`): nada anterior a ese momento se responde.
2. El ultimo mensaje enviado por nosotros (`FromMe`): todo lo que esta antes o en ese mensaje ya fue atendido.

La logica vive en `FiltrarMensajesNuevos`:

```csharp
static List<InboundMessage> FiltrarMensajesNuevos(IReadOnlyList<InboundMessage> mensajes, DateTimeOffset? desde) {
    List<InboundMessage> mensajesCronologicos = mensajes
        .OrderBy(mensaje => mensaje.Timestamp ?? DateTimeOffset.MinValue)
        .ThenBy(mensaje => mensaje.Id, StringComparer.Ordinal)
        .ToList();

    int indiceUltimoMensajePropio = mensajesCronologicos.FindLastIndex(mensaje => mensaje.FromMe);
    int indiceUltimoMensajeAntesDeInicio = desde is null
        ? -1
        : mensajesCronologicos.FindLastIndex(mensaje => mensaje.Timestamp is not null && mensaje.Timestamp < desde);
    int indiceInicio = Math.Max(indiceUltimoMensajePropio, indiceUltimoMensajeAntesDeInicio);

    IEnumerable<InboundMessage> mensajesDespuesDeInicio = indiceInicio >= 0
        ? mensajesCronologicos.Skip(indiceInicio + 1)
        : mensajesCronologicos;

    return mensajesDespuesDeInicio
        .Where(EsTextoEntrante)
        .ToList();
}

static bool EsTextoEntrante(InboundMessage mensaje) => !mensaje.FromMe && !string.IsNullOrWhiteSpace(mensaje.Text);
```

Pasos:

1. Ordena los mensajes en orden cronologico (por `Timestamp`, y por `Id` para desempatar).
2. Busca el indice del ultimo mensaje propio y el del ultimo mensaje anterior al arranque.
3. Se queda con el indice mas avanzado de los dos: esa es la linea divisoria.
4. Toma todo lo que viene despues de esa linea.
5. Filtra para quedarse solo con mensajes entrantes que tengan texto.

Detalle importante: por esto leemos todos los mensajes (no solo los del contacto), porque necesitamos ver tambien nuestros propios mensajes (`FromMe`) para ubicar la ultima respuesta enviada.

## 8. Recibir el texto nuevo

`RecibirTexto` junta todo lo anterior y devuelve un unico texto listo para el asistente:

```csharp
public static async Task<string?> RecibirTexto(string contacto, DateTimeOffset? desde = null) {
    CommandResult resultado = await EjecutarWacli("--json", "messages", "list", "--chat", contacto, "--limit", "50");
    if (resultado.ExitCode != 0) {
        Console.Error.WriteLine($"No se pudieron leer mensajes con wacli: {resultado.StdErr}");
        return null;
    }

    IReadOnlyList<InboundMessage> mensajes = ParsearMensajes(resultado.StdOut, contacto);
    List<string> mensajesFiltrados = FiltrarMensajesNuevos(mensajes, desde)
        .Select(mensaje => mensaje.Text.Trim())
        .Where(texto => texto.Length > 0)
        .ToList();
    if (mensajesFiltrados.Count == 0) { return null; }

    return string.Join(Environment.NewLine, mensajesFiltrados);
}
```

Si el contacto mando varios mensajes seguidos, se combinan en un solo texto separado por saltos de linea. El asistente los lee como un unico turno. Si no hay nada nuevo, devuelve `null` y el bucle sigue esperando.

## 9. Comando de salida

La salida es muy simple:

```csharp
static bool EsComandoFinalizar(string texto) => texto.Contains(ComandoFinalizar, StringComparison.OrdinalIgnoreCase);
```

Si el texto nuevo contiene `/finalizar` (sin importar mayusculas), el bucle hace `break` y el bloque `finally` detiene `wacli sync`.

## 10. Modulo de IA: `AgenteSecretaria`

`AgenteSecretaria` encapsula la interaccion con `Microsoft.Extensions.AI`. Es una clase con estado: guarda el cliente, las opciones y el historial de la conversacion.

```csharp
sealed class AgenteSecretaria {
    readonly IChatClient cliente;
    readonly ChatOptions opciones;
    readonly List<ChatMessage> conversacion;

    public AgenteSecretaria(string claveApi, string modelo, string promptSistema) {
        cliente = CrearCliente(claveApi, modelo);
        opciones = CrearOpciones();
        conversacion = [new(ChatRole.System, promptSistema)];
    }
    ...
}
```

El constructor arma todo de una vez: crea el cliente, registra las herramientas y deja el historial inicial con el mensaje `System`. Por eso el flujo principal puede escribir simplemente `new(claveApi, Modelo, promptSistema)`.

### 10.1. Crear el cliente

```csharp
static IChatClient CrearCliente(string claveApi, string modelo) => new ChatClientBuilder(
        new OpenAIClient(claveApi).GetChatClient(modelo).AsIChatClient())
    .UseFunctionInvocation()
    .Build();
```

Piezas:

| Pieza                     | Que hace                                       |
| ------------------------- | ---------------------------------------------- |
| `OpenAIClient(claveApi)`  | Crea el cliente del proveedor.                 |
| `GetChatClient(modelo)`   | Selecciona el modelo.                          |
| `AsIChatClient()`         | Lo adapta a la abstraccion MEAI.               |
| `ChatClientBuilder`       | Permite agregar comportamiento.                |
| `UseFunctionInvocation()` | Permite que el modelo invoque herramientas C#. |

### 10.2. Registrar herramientas

```csharp
static ChatOptions CrearOpciones() => new() {
    Tools =
    [
        AIFunctionFactory.Create(ArchivosAgente.LeerArchivo),
        AIFunctionFactory.Create(ArchivosAgente.EscribirArchivo),
        AIFunctionFactory.Create(ArchivosAgente.ListarArchivos)
    ]
};
```

`AIFunctionFactory.Create` convierte metodos C# en herramientas disponibles para el modelo. El nombre del metodo es el nombre con el que el modelo invoca la herramienta.

### 10.3. Responder

```csharp
public async Task<string> ProcesarMensaje(string textoWhatsapp) {
    Console.WriteLine($"[{DateTimeOffset.Now:yyyy-MM-dd HH:mm:ss}] usuario: {textoWhatsapp}");

    conversacion.Add(new(ChatRole.User, textoWhatsapp));

    ChatResponse respuesta = await cliente.GetResponseAsync(conversacion, opciones);
    conversacion.AddMessages(respuesta);

    return respuesta.Text.Trim();
}
```

El historial (`conversacion`) se actualiza en cada turno. Sin esto, el modelo no recordaria mensajes anteriores. Como el historial es un campo de la clase, no hay que pasarlo de un lado a otro: el asistente lo conserva entre llamadas.

## 11. Herramientas del agente: `ArchivosAgente`

El asistente necesita manipular archivos porque administra `CONTACTOS.md`.

Las herramientas son:

```csharp
public static async Task<string> LeerArchivo(string rutaRelativa)
public static async Task<string> EscribirArchivo(string rutaRelativa, string contenido)
public static string ListarArchivos(string patron = "*")
```

Usan atributos `Description` para que el modelo entienda como llamarlas:

```csharp
[Description("Lee un archivo de texto dentro de la carpeta de trabajo.")]
public static async Task<string> LeerArchivo([Description("Ruta relativa del archivo a leer.")] string rutaRelativa) {
    string ruta = ObtenerRutaSegura(rutaRelativa);
    if (!File.Exists(ruta)) { return $"No encontre el archivo: {rutaRelativa}"; }
    return await File.ReadAllTextAsync(ruta);
}
```

### 11.1. Seguridad de rutas

El asistente no debe leer ni escribir fuera del directorio de trabajo. Por eso se valida la ruta:

```csharp
static string ObtenerRutaSegura(string rutaRelativa) {
    string raiz = Path.GetFullPath(RaizTrabajo);
    string rutaCompleta = Path.GetFullPath(Path.Combine(raiz, rutaRelativa));

    if (!rutaCompleta.StartsWith(raiz + Path.DirectorySeparatorChar, StringComparison.Ordinal) && rutaCompleta != raiz) {
        throw new InvalidOperationException("La ruta debe estar dentro de la carpeta de trabajo.");
    }

    return rutaCompleta;
}
```

Esto evita rutas como `../../otro-archivo`.

## 12. Como funciona wacli

`wacli` es una CLI para WhatsApp. La aplicacion no implementa el protocolo de WhatsApp; delega esa parte a `wacli`.

Segun su ayuda:

```text
wacli is a WhatsApp CLI for syncing, searching, and sending from local scripts.
```

Conceptualmente, `wacli` hace tres cosas importantes para este bot:

1. Autentica una cuenta de WhatsApp.
2. Mantiene una base local de mensajes y contactos.
3. Permite leer y enviar mensajes desde comandos de terminal.

### 12.1. Autenticacion

Antes de correr el bot, la cuenta debe estar autenticada:

```bash
wacli auth
```

Normalmente esto muestra un QR o inicia el flujo de autenticacion. Una vez autenticado, `wacli sync` puede sincronizar sin volver a mostrar QR.

### 12.2. Sincronizacion

El comando importante es:

```bash
wacli sync --follow --refresh-contacts
```

Significado:

| Parte                | Funcion                                                 |
| -------------------- | ------------------------------------------------------- |
| `sync`               | Sincroniza mensajes desde WhatsApp hacia la base local. |
| `--follow`           | Mantiene la sincronizacion activa.                      |
| `--refresh-contacts` | Actualiza contactos en la base local.                   |

`wacli sync` es el proceso que mantiene vivos los datos. El bot lo arranca en segundo plano al inicio.

### 12.3. Leer mensajes

Para leer mensajes usamos:

```bash
wacli --json messages list --chat "+5493815343458" --limit 50
```

Significado:

| Parte           | Funcion                                     |
| --------------- | ------------------------------------------- |
| `--json`        | Devuelve JSON en lugar de una tabla humana. |
| `messages list` | Lista mensajes desde la base local.         |
| `--chat`        | Filtra por chat/contacto.                   |
| `--limit 50`    | Devuelve los ultimos 50.                    |

No usamos `--from-them`: leemos tambien nuestros propios mensajes a proposito, porque el filtro en C# necesita ver el ultimo mensaje enviado por nosotros para ubicar la linea divisoria (ver seccion 7).

### 12.4. Enviar mensajes

Para responder usamos:

```bash
wacli send text --to "+5493815343458" --message "Texto de respuesta"
```

Significado:

| Parte       | Funcion                                               |
| ----------- | ----------------------------------------------------- |
| `send text` | Envia un mensaje de texto.                            |
| `--to`      | Destinatario: numero, JID, nombre de contacto o chat. |
| `--message` | Texto a enviar.                                       |

### 12.5. JSON de salida

La salida JSON de `messages list` tiene una estructura similar a:

```json
{
  "success": true,
  "data": {
    "messages": [
      {
        "ChatJID": "5493815343458@s.whatsapp.net",
        "ChatName": "Alejandro Di Battista",
        "MsgID": "AC35583875E6E18ACAEB27005FCD14E8",
        "Timestamp": "2026-06-23T22:51:55Z",
        "FromMe": false,
        "Text": "Hola",
        "DisplayText": "Hola"
      }
    ]
  },
  "error": null
}
```

El bot solo necesita algunos campos:

| Campo         | Uso                                           |
| ------------- | --------------------------------------------- |
| `MsgID`       | Identificar el mensaje y desempatar el orden. |
| `ChatJID`     | Identificar contacto/chat.                    |
| `Text`        | Texto que va al asistente.                    |
| `DisplayText` | Texto alternativo si `Text` esta vacio.       |
| `FromMe`      | Distinguir mensajes propios de los entrantes. |
| `Timestamp`   | Ordenar mensajes y ubicar la linea divisoria. |

## 13. Construir el modulo `ClienteWhatsApp`

`ClienteWhatsApp` es un adaptador. Su objetivo es esconder que estamos usando comandos externos.

El resto de la app no deberia saber si WhatsApp viene de `wacli`, una API HTTP o una base de datos. Solo necesita estos metodos:

```csharp
public static Process IniciarSincronizacion()
public static void DetenerSincronizacion(Process? procesoSincronizacion)
public static Task<string?> RecibirTexto(string contacto, DateTimeOffset? desde = null)
public static Task EnviarTexto(string contacto, string mensaje)
```

### 13.1. Constante del modulo

```csharp
static class ClienteWhatsApp {
    const string EjecutableWacli = "wacli";
    ...
}
```

Los argumentos de cada comando se arman en cada metodo como una lista de strings (ver 13.4 y 14). Si cambia la sintaxis de `wacli`, se toca este modulo y no el bot completo.

### 13.2. Iniciar wacli sync en segundo plano

```csharp
public static Process IniciarSincronizacion() {
    ProcessStartInfo infoInicio = CrearInfoInicioWacli(redirigir: false, "sync", "--follow", "--refresh-contacts");
    Process proceso = Process.Start(infoInicio) ?? throw new InvalidOperationException("No se pudo iniciar la sincronizacion de WhatsApp con wacli.");
    Console.WriteLine($"Sincronizacion de WhatsApp iniciada con wacli. PID: {proceso.Id}");
    return proceso;
}
```

Punto clave: para `sync` no redirigimos la salida (`redirigir: false`). Es un proceso persistente que queda vivo mientras el bot corre.

### 13.3. Detener wacli sync

```csharp
public static void DetenerSincronizacion(Process? procesoSincronizacion) {
    if (procesoSincronizacion is null) { return; }
    if (!procesoSincronizacion.HasExited) { procesoSincronizacion.Kill(entireProcessTree: true); }
    procesoSincronizacion.Dispose();
}
```

Como el bot solo termina con `/finalizar`, este metodo se llama desde `finally` para garantizar que `wacli sync` no quede vivo.

### 13.4. Enviar texto desde un comando externo

```csharp
public static async Task EnviarTexto(string contacto, string mensaje) {
    CommandResult resultado = await EjecutarWacli("send", "text", "--to", contacto, "--message", mensaje);
    if (resultado.ExitCode != 0) { throw new InvalidOperationException($"No se pudo enviar el mensaje con wacli: {resultado.StdErr}"); }
}
```

Aca, si falla el envio, lanzamos excepcion porque el bot no pudo cumplir su accion principal. Notar que el contacto y el mensaje se pasan como argumentos sueltos, no concatenados en un string.

## 14. Ejecutar comandos externos desde C#

Esta es una parte clave del tutorial.

En C#, un comando externo se ejecuta con `Process` y `ProcessStartInfo`.

### 14.1. Configurar el proceso

```csharp
static ProcessStartInfo CrearInfoInicioWacli(bool redirigir, params string[] argumentos) {
    ProcessStartInfo infoInicio = new(EjecutableWacli) {
        UseShellExecute  = false,
        RedirectStandardOutput = redirigir,
        RedirectStandardError  = redirigir,
        CreateNoWindow   = true,
        WorkingDirectory = Environment.CurrentDirectory
    };
    foreach (string argumento in argumentos) { infoInicio.ArgumentList.Add(argumento); }
    return infoInicio;
}
```

Cada propiedad importa:

| Propiedad                 | Explicacion                                             |
| ------------------------- | ------------------------------------------------------- |
| `UseShellExecute = false` | Ejecuta el proceso directamente, no a traves del shell. |
| `RedirectStandardOutput`  | Si es `true`, permite leer la salida normal.            |
| `RedirectStandardError`   | Si es `true`, permite leer errores.                     |
| `CreateNoWindow = true`   | No abre otra ventana de terminal.                       |
| `WorkingDirectory`        | Ejecuta desde el directorio actual.                     |

El parametro `redirigir` permite reusar el mismo metodo para `sync` (sin redirigir) y para los comandos que leen salida (redirigiendo).

### 14.2. Argumentos seguros con `ArgumentList`

En lugar de armar un unico string de argumentos y escapar comillas a mano, cada argumento se agrega por separado a `ArgumentList`:

```csharp
infoInicio.ArgumentList.Add(argumento);
```

Esto es importante: los contactos y mensajes pueden tener espacios o comillas. Al pasar cada argumento por separado, el sistema operativo se encarga del quoting de forma segura. Por ejemplo, un mensaje como:

```text
Hola "Juan", como estas?
```

llega intacto al proceso, sin que tengamos que escapar nada manualmente. Por eso los metodos llaman a `EjecutarWacli("send", "text", "--to", contacto, "--message", mensaje)` en vez de concatenar un comando.

### 14.3. Ejecutar y capturar salida

```csharp
static async Task<CommandResult> EjecutarWacli(params string[] argumentos) {
    ProcessStartInfo infoInicio = CrearInfoInicioWacli(redirigir: true, argumentos);
    using Process proceso = Process.Start(infoInicio) ?? throw new InvalidOperationException("No se pudo ejecutar wacli.");

    Task<string> salidaEstandar = proceso.StandardOutput.ReadToEndAsync();
    Task<string> errorEstandar = proceso.StandardError.ReadToEndAsync();
    await proceso.WaitForExitAsync();

    return new(proceso.ExitCode, await salidaEstandar, await errorEstandar);
}
```

La funcion devuelve un record simple:

```csharp
sealed record CommandResult(int ExitCode, string StdOut, string StdErr);
```

Esto es mejor que devolver solo un string porque distingue:

- Si el comando funciono (`ExitCode`).
- Que imprimio normalmente (`StdOut`).
- Que imprimio como error (`StdErr`).

### 14.4. Por que leer stdout y stderr

Un programa de terminal tiene dos salidas:

| Salida   | Uso                                                  |
| -------- | ---------------------------------------------------- |
| `stdout` | Resultado normal. En nuestro caso, JSON de mensajes. |
| `stderr` | Errores o advertencias.                              |

Si `wacli messages list` funciona, el JSON viene por `stdout`. Si falla, el motivo suele venir por `stderr`.

## 15. Parsear la salida JSON de wacli

Primero se definen clases que representan el JSON. Estos tipos conservan los nombres originales de los campos de `wacli`:

```csharp
sealed class WacliMessageList {
    public WacliMessageData? Data { get; set; }
}

sealed class WacliMessageData {
    public List<WacliStoredMessage> Messages { get; set; } = [];
}

sealed class WacliStoredMessage {
    public string? MsgID { get; set; }
    public string? ChatJID { get; set; }
    public string? ChatName { get; set; }
    public string? SenderJID { get; set; }
    public string? SenderName { get; set; }
    public string? Text { get; set; }
    public string? DisplayText { get; set; }
    public string? Snippet { get; set; }
    public bool FromMe { get; set; }
    public DateTimeOffset? Timestamp { get; set; }
}
```

Luego se deserializa dentro de `ParsearMensajes`:

```csharp
static IReadOnlyList<InboundMessage> ParsearMensajes(string salida, string contactoPorDefecto) {
    try {
        WacliMessageList? respuesta = JsonSerializer.Deserialize(salida, WhatsAppJsonContext.Default.WacliMessageList);
        List<WacliStoredMessage> mensajes = respuesta?.Data?.Messages ?? [];

        return mensajes.Select(AMensajeEntrante).ToList();
    } catch (JsonException) {
        return salida
            .Split('\n', StringSplitOptions.RemoveEmptyEntries | StringSplitOptions.TrimEntries)
            .Select((linea, indice) => new InboundMessage($"line:{indice}:{linea.GetHashCode()}", contactoPorDefecto, linea, false, DateTimeOffset.UtcNow))
            .ToList();
    }
}
```

El `catch (JsonException)` es un respaldo: si la salida no fuera JSON valido, igual se arma una lista basica para no romper el bot.

Cada mensaje del JSON se transforma a un tipo interno mas simple:

```csharp
static InboundMessage AMensajeEntrante(WacliStoredMessage mensaje) => new(
    Id: mensaje.MsgID ?? Guid.NewGuid().ToString("N"),
    Contact: mensaje.ChatJID ?? mensaje.SenderJID ?? mensaje.ChatName ?? mensaje.SenderName ?? string.Empty,
    Text: PrimerNoVacio(mensaje.Text, mensaje.DisplayText, mensaje.Snippet) ?? string.Empty,
    FromMe: mensaje.FromMe,
    Timestamp: mensaje.Timestamp);
```

El tipo que usa el bot es:

```csharp
sealed record InboundMessage(string Id, string Contact, string Text, bool FromMe, DateTimeOffset? Timestamp);
```

`PrimerNoVacio` elige el primer texto disponible entre `Text`, `DisplayText` y `Snippet`:

```csharp
static string? PrimerNoVacio(params string?[] valores) => valores.FirstOrDefault(valor => !string.IsNullOrWhiteSpace(valor));
```

Esto mantiene simple al resto del programa.

## 16. JsonSerializerContext

El archivo usa source generation de JSON:

```csharp
[JsonSourceGenerationOptions(PropertyNameCaseInsensitive = true)]
[JsonSerializable(typeof(WacliMessageList))]
partial class WhatsAppJsonContext : JsonSerializerContext;
```

En una linea: le estamos diciendo a `System.Text.Json` que estructura esperamos recibir de `wacli`.

`PropertyNameCaseInsensitive = true` permite que el parseo no dependa estrictamente de mayusculas y minusculas.

## 17. Prompt desde AGENTS.md

El prompt se carga desde archivo:

```csharp
static async Task<string> LeerPromptSistema(string archivoAgentes, string promptPorDefecto) {
    if (!File.Exists(archivoAgentes)) { return promptPorDefecto; }
    string prompt = await File.ReadAllTextAsync(archivoAgentes);
    return string.IsNullOrWhiteSpace(prompt) ? promptPorDefecto : prompt;
}
```

Esto permite cambiar el comportamiento del bot sin tocar codigo.

## 20. Errores comunes

| Problema                 | Causa probable                                | Solucion                                               |
| ------------------------ | --------------------------------------------- | ------------------------------------------------------ |
| No responde              | No llegan mensajes nuevos.                    | Probar `wacli messages list`.                          |
| Responde mensajes viejos | El reloj o la marca de arranque no coinciden. | Revisar `iniciadoEn` y `FiltrarMensajesNuevos`.        |
| Falla IA                 | Falta `OPENAI_API_KEY`.                       | Exportar la variable.                                  |
| Falla envio              | `wacli send text` no resuelve el contacto.    | Probar envio manual.                                   |
| No modifica archivos     | El modelo no invoca herramientas.             | Revisar `UseFunctionInvocation` y `ChatOptions.Tools`. |
| Queda `wacli sync` vivo  | No llego `/finalizar`.                        | Enviar `/finalizar` desde WhatsApp.                    |

## 21. Resumen para explicar en clase

Una explicacion corta:

```text
El bot arranca wacli sync, lee los ultimos mensajes con wacli messages list, descarta lo viejo usando la hora de arranque y su ultimo mensaje enviado, usa Microsoft.Extensions.AI para generar una respuesta con herramientas de archivos y envia la respuesta con wacli send text. El ciclo sigue hasta recibir /finalizar.
```

Secuencia conceptual:

```text
1. wacli sync mantiene la base local actualizada.
2. C# consulta la base local con wacli messages list.
3. C# filtra mensajes nuevos por marca de tiempo y ultimo mensaje propio.
4. Microsoft.Extensions.AI genera la respuesta.
5. Las herramientas permiten leer/escribir archivos.
6. C# envia la respuesta usando wacli send text.
7. /finalizar corta el bucle.
```
