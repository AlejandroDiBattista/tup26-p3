# Tutorial: asistente de programación mínimo con tools

En este tutorial vamos a construir, desde cero, un asistente de programación que se ejecuta en una consola y puede usar tres herramientas:

- `listar-archivos`: conoce qué archivos existen.
- `leer-archivo`: obtiene el contenido de un archivo.
- `escribir-archivo`: crea o reemplaza un archivo.

El código completo se encuentra en [40.8-asistente-tools-minimo.cs](40.8-asistente-tools-minimo.cs).

---

## 1. Qué es realmente un asistente con tools

Un modelo de lenguaje solamente recibe datos y genera una respuesta. No puede leer nuestro disco por sí mismo.

Si le preguntamos:

> ¿Qué contiene `programa.cs`?

el modelo no conoce ese archivo. Para resolverlo, nuestra aplicación le ofrece una función llamada `leer-archivo`.

El ciclo completo es el siguiente:

1. La aplicación envía al modelo el mensaje del usuario y la descripción de las tools disponibles.
2. El modelo decide si necesita usar una tool.
3. Si necesita una, responde con el nombre de la tool y sus argumentos. Por ejemplo: `leer-archivo(ruta: "programa.cs")`.
4. La aplicación ejecuta la función C# correspondiente.
5. La aplicación envía el resultado de la función al modelo.
6. El modelo utiliza ese resultado para redactar la respuesta final.

La decisión de usar una tool pertenece al modelo. La ejecución de la tool pertenece a nuestro programa.

Este flujo coincide con el proceso de function calling documentado por [OpenAI](https://developers.openai.com/api/docs/guides/function-calling). En este ejemplo, `Microsoft.Extensions.AI` se ocupa automáticamente de repetir las llamadas necesarias entre los pasos 2 y 6.

## 2. Estructura mínima

Vamos a utilizar un archivo ejecutable de C# de .NET 10. Las primeras líneas declaran el intérprete y las dependencias:

```csharp
#!/usr/bin/env -S dotnet run
#:package DotNetEnv@*
#:package Microsoft.Extensions.AI@10.4.0
#:package Microsoft.Extensions.AI.OpenAI@10.4.0
```

Cada dependencia cumple una función concreta:

| Paquete                          | Responsabilidad                                                                       |
|----------------------------------|---------------------------------------------------------------------------------------|
| `DotNetEnv`                      | Carga variables desde el archivo `.env`.                                              |
| `Microsoft.Extensions.AI`        | Define el cliente, los mensajes, las tools y la invocación automática.                |
| `Microsoft.Extensions.AI.OpenAI` | Adapta el cliente oficial de OpenAI a las abstracciones de `Microsoft.Extensions.AI`. |

Importamos los espacios de nombres necesarios:

```csharp
using System.ComponentModel;
using Microsoft.Extensions.AI;
using OpenAIChatClient = OpenAI.Chat.ChatClient;
```

`DescriptionAttribute`, definido en `System.ComponentModel`, permite describir los parámetros de las tools. Esas descripciones ayudan al modelo a construir argumentos correctos.

## 3. Configurar la clave de API

La aplicación necesita una clave de la API de OpenAI. La clave no debe escribirse dentro del código.

En el mismo directorio desde el que se ejecutará el programa, crear un archivo `.env`:

```env
OPENAI_API_KEY=la_clave_personal
```

Agregar `.env` al archivo `.gitignore` para evitar publicarlo:

```gitignore
.env
```

El programa carga y valida la variable:

```csharp
DotNetEnv.Env.Load();

var apiKey = Environment.GetEnvironmentVariable("OPENAI_API_KEY");
if (string.IsNullOrWhiteSpace(apiKey)) {
    throw new InvalidOperationException("Falta OPENAI_API_KEY en el archivo .env.");
}
```

La aplicación se detiene inmediatamente si no encuentra una clave. Es preferible este error concreto a permitir que la primera consulta falle con un mensaje menos claro.

## 4. Definir un workspace

Una tool de archivos no debería operar libremente sobre todo el disco. Vamos a limitarla a un directorio llamado `workspace`:

```csharp
var workspace = Path.GetFullPath("workspace");
Directory.CreateDirectory(workspace);
```

`Path.GetFullPath` transforma la ruta relativa en una ruta absoluta. Las tres tools utilizarán siempre este mismo directorio como raíz.

Si el programa se ejecuta desde `clases`, los archivos administrados quedarán dentro de:

```text
clases/workspace/
```

Esta separación evita que una prueba normal modifique el código del propio asistente.

## 5. Crear el cliente y habilitar las tools

Primero construimos el cliente básico de OpenAI. Después agregamos una etapa que ejecuta automáticamente las funciones solicitadas por el modelo:

```csharp
IChatClient chat = new OpenAIChatClient("gpt-5.5", apiKey)
    .AsIChatClient()
    .AsBuilder()
    .UseFunctionInvocation()
    .Build();
```

Cada llamada tiene un propósito:

1. `OpenAIChatClient` crea el cliente concreto para el modelo `gpt-5.5`.
2. `AsIChatClient` lo expone mediante la interfaz común `IChatClient`.
3. `AsBuilder` inicia una cadena de componentes alrededor del cliente.
4. `UseFunctionInvocation` agrega el componente que detecta y ejecuta tool calls.
5. `Build` construye el cliente definitivo.

Sin `UseFunctionInvocation`, el modelo podría solicitar una tool, pero nuestro programa tendría que interpretar y ejecutar manualmente esa solicitud. Con este componente, la biblioteca implementa el ciclo automático. Microsoft documenta este patrón en su [guía de invocación de funciones .NET](https://learn.microsoft.com/es-es/dotnet/ai/quickstarts/use-function-calling).

## 6. Escribir las tres funciones C#

Antes de convertirlas en tools, las herramientas son funciones C# normales. Se pueden comprender y probar sin inteligencia artificial.

### 6.1. Listar archivos

```csharp
string ListarArchivos(
    [Description("Ruta relativa del directorio. Usar punto para la raíz.")] string ruta = ".") {
    var rutaCompleta = ResolverRuta(ruta);

    if (!Directory.Exists(rutaCompleta)) return $"No existe el directorio: {ruta}";

    var elementos = Directory.EnumerateFileSystemEntries(rutaCompleta).Select(Path.GetFileName);

    return string.Join(Environment.NewLine, elementos);
}
```

La función recibe una ruta relativa. El valor `.` representa la raíz del workspace. Si el directorio existe, devuelve un nombre por línea.

La función devuelve texto porque ese resultado será enviado al modelo. No imprime directamente en la consola.

### 6.2. Leer un archivo

```csharp
string LeerArchivo(
    [Description("Ruta relativa del archivo que se quiere leer.")] string ruta) {
    var rutaCompleta = ResolverRuta(ruta);

    return File.Exists(rutaCompleta)
        ? File.ReadAllText(rutaCompleta)
        : $"No existe el archivo: {ruta}";
}
```

Si el archivo existe, devuelve su contenido completo. Si no existe, devuelve un mensaje que el modelo puede interpretar y explicar al usuario.

### 6.3. Escribir un archivo

```csharp
string EscribirArchivo(
    [Description("Ruta relativa del archivo que se quiere escribir.")] string ruta,
    [Description("Contenido completo que se guardará en el archivo.")] string contenido) {
    var rutaCompleta = ResolverRuta(ruta);
    Directory.CreateDirectory(Path.GetDirectoryName(rutaCompleta)!);
    File.WriteAllText(rutaCompleta, contenido);
    return $"Archivo escrito: {ruta}";
}
```

Esta función crea los directorios intermedios, escribe el contenido completo y devuelve una confirmación.

`File.WriteAllText` reemplaza el contenido si el archivo ya existe. Por eso el prompt indicará que debe leer un archivo existente antes de modificarlo.

## 7. Resolver rutas de manera controlada

Las tres funciones llaman a un único helper:

```csharp
string ResolverRuta(string ruta) {
    var rutaCompleta = Path.GetFullPath(Path.Combine(workspace, ruta));
    var prefijoValido = workspace.TrimEnd(Path.DirectorySeparatorChar)
        + Path.DirectorySeparatorChar;

    if (rutaCompleta != workspace &&
        !rutaCompleta.StartsWith(prefijoValido, StringComparison.Ordinal)) {
        throw new UnauthorizedAccessException("La ruta está fuera del workspace.");
    }

    return rutaCompleta;
}
```

Supongamos que el workspace es `/curso/workspace`:

| Entrada           | Ruta resuelta                      | Resultado |
|-------------------|------------------------------------|-----------|
| `programa.cs`     | `/curso/workspace/programa.cs`     | Permitida |
| `ejemplos/app.cs` | `/curso/workspace/ejemplos/app.cs` | Permitida |
| `../secreto.txt`  | `/curso/secreto.txt`               | Rechazada |

El control se realiza después de normalizar la ruta. De esta forma, `..` no puede utilizarse para salir del workspace.

Esta verificación es suficiente para el ejemplo didáctico, pero no constituye un sandbox de producción. Una aplicación real también debe considerar enlaces simbólicos, permisos, tamaños máximos, extensiones permitidas y confirmación del usuario antes de sobrescribir información.

## 8. Convertir las funciones en tools

El modelo no recibe métodos C# directamente. Recibe el nombre, la descripción y un esquema de parámetros de cada tool.

`AIFunctionFactory.Create` toma una función C# y genera esa representación:

```csharp
var opciones = new ChatOptions {
    Tools = [
        AIFunctionFactory.Create(ListarArchivos, new() {
            Name = "listar-archivos",
            Description = "Lista los archivos y directorios de una ruta del workspace."
        }),
        AIFunctionFactory.Create(LeerArchivo, new() {
            Name = "leer-archivo",
            Description = "Lee el contenido completo de un archivo del workspace."
        }),
        AIFunctionFactory.Create(EscribirArchivo, new() {
            Name = "escribir-archivo",
            Description = "Crea o reemplaza un archivo de texto dentro del workspace."
        })
    ]
};
```

Hay dos niveles de descripción:

- `Description` dentro de `AIFunctionFactoryOptions` explica para qué sirve la tool.
- `[Description]` sobre cada parámetro explica qué dato debe proporcionar el modelo.

`AIFunctionFactory` utiliza la firma de la función para generar el esquema JSON de sus argumentos. La [referencia de AIFunctionFactory](https://learn.microsoft.com/en-us/dotnet/api/microsoft.extensions.ai.aifunctionfactory?view=net-10.0-pp) describe esta conversión.

Las tools no se colocan en el prompt. Se envían mediante `ChatOptions.Tools`, como capacidades estructuradas que el modelo puede seleccionar.

## 9. Crear el historial y el prompt mínimo

Una conversación es una lista ordenada de mensajes:

```csharp
var mensajes = new List<ChatMessage> {
    new(ChatRole.System, """
    Sos un asistente de programación. Respondé en español.
    Usá las herramientas para listar, leer y escribir archivos cuando sea necesario.
    Antes de modificar un archivo existente, leelo.
    """)
};
```

El primer mensaje tiene rol `System`. Su función es definir reglas estables para toda la conversación.

El prompt está dentro del programa porque buscamos la versión más pequeña posible. En una aplicación mayor podría cargarse desde un archivo o desde configuración.

## 10. Implementar el ciclo de conversación

El chatbot repite cuatro operaciones: leer, validar, consultar y mostrar.

```csharp
while (true) {
    Console.Write("vos> ");
    var texto = Console.ReadLine();

    if (texto is null || texto.Equals("/salir", StringComparison.OrdinalIgnoreCase)) break;
    if (string.IsNullOrWhiteSpace(texto)) continue;

    mensajes.Add(new(ChatRole.User, texto));

    try {
        var respuesta = await chat.GetResponseAsync(mensajes, opciones);
        mensajes.Add(new(ChatRole.Assistant, respuesta.Text ?? ""));
        Console.WriteLine($"asistente> {respuesta.Text}\n");
    } catch (Exception ex) {
        Console.WriteLine($"Error: {ex.Message}\n");
    }
}
```

La línea central es:

```csharp
var respuesta = await chat.GetResponseAsync(mensajes, opciones);
```

`mensajes` contiene el contexto de la conversación. `opciones` contiene las tools disponibles.

No utilizamos streaming. `await` espera hasta que se completan todas las tool calls y se obtiene la respuesta final. Recién entonces se imprime el texto.

Después agregamos la respuesta al historial. Gracias a esto, la siguiente consulta puede hacer referencia a mensajes anteriores.

## 11. Ejecutar el programa

Desde el directorio `clases`:

```bash
dotnet run 40.8-asistente-tools-minimo.cs
```

Al iniciar, el programa crea automáticamente el directorio `workspace`.

Probar las tools por separado con estas solicitudes:

```text
Creá saludo.txt con el texto Hola mundo.
```

```text
Leé saludo.txt y explicame qué contiene.
```

```text
Listá los archivos disponibles.
```

Luego probar una tarea que requiera varias tools:

```text
Creá operaciones.cs con una función Sumar. Después leé el archivo y explicame el código.
```

En esa última solicitud, el modelo puede llamar a `escribir-archivo` y luego a `leer-archivo` antes de presentar su respuesta final.

Para terminar:

```text
/salir
```

## 12. Qué conceptos deben quedar claros

1. El modelo no ejecuta C# ni accede directamente al disco.
2. Una tool es una función de nuestra aplicación expuesta mediante nombre, descripción y parámetros.
3. El modelo decide cuándo solicitar una tool; la aplicación conserva el control de su ejecución.
4. El resultado de una tool vuelve al modelo para que pueda continuar razonando y responder.
5. `UseFunctionInvocation` automatiza el intercambio de tool calls y resultados.
6. `ChatOptions.Tools` define las capacidades disponibles en una consulta.
7. La lista de `ChatMessage` conserva el contexto entre turnos.
8. Las rutas y argumentos generados por un modelo deben considerarse datos no confiables y validarse.

Con estos elementos ya existe un asistente de programación real, aunque deliberadamente pequeño. La interfaz gráfica, el streaming, la persistencia y las aprobaciones son mejoras posteriores; no son necesarias para comprender el mecanismo fundamental.
