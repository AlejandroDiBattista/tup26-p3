# El API compatible con OpenAI: completar texto como primitiva de procesamiento

## El problema

Queremos hablarle a un modelo de lenguaje desde nuestro código. No desde un chat web, no desde una librería que esconde todo, sino mandando un pedido HTTP nosotros mismos y leyendo la respuesta. La idea es entender qué viaja por el cable, porque una vez que lo entendés, te das cuenta de que **toda la potencia del modelo se reduce a una sola operación: completar texto**. Y sobre esa operación, con un buen prompt, podés construir traductores, extractores de datos, generadores de código y consultores sobre tus propios datos.

Este apunte recorre el archivo `40.2-openai-httpclient.cs`, un programa de un solo archivo (.NET 10, file-based) que hace exactamente eso con `HttpClient` puro, sin SDK de por medio.

---

## El "API compatible con OpenAI"

OpenAI definió un formato de pedido y respuesta para su endpoint de chat. Ese formato se volvió tan común que muchísimos otros proveedores (Gemini, Groq, DeepSeek, Ollama corriendo local, etc.) ofrecen un endpoint que **habla el mismo dialecto**. A eso le decimos "compatible con OpenAI".

La consecuencia práctica es enorme: escribís el cliente una sola vez y cambiás de proveedor tocando nada más que tres variables de entorno. Mirá cómo arranca el programa:

```csharp
string proveedor = (args.Length > 0 ? args[0] : "openai").ToUpper();

string  URL     = Environment.GetEnvironmentVariable($"{proveedor}_API_URL") ?? "";
string? API_KEY = Environment.GetEnvironmentVariable($"{proveedor}_API_KEY");
string  MODELO  = Environment.GetEnvironmentVariable($"{proveedor}_MODEL") ?? "gpt-5.5";
```

Pasás `openai` o `gemini` por línea de comando y el programa arma los nombres de variable (`OPENAI_API_URL`, `GEMINI_API_URL`, etc.) sobre la marcha. El `.env` se carga con `DotNetEnv.Env.Load()` al inicio. Un `.env` típico:

```
OPENAI_API_URL=https://api.openai.com/v1/chat/completions
OPENAI_API_KEY=sk-...
OPENAI_MODEL=gpt-5.5

GEMINI_API_URL=https://generativelanguage.googleapis.com/v1beta/openai/chat/completions
GEMINI_API_KEY=...
GEMINI_MODEL=gemini-2.5-flash
```

> **Por qué variables de entorno y no la clave en el código.** La API key es un secreto. Si la escribís en el `.cs` y subís el archivo a GitHub, regalaste tu clave (y tu plata, porque estos servicios se pagan por uso). El `.env` queda fuera del control de versiones con un `.gitignore`.

### Antes de correr el ejemplo: configurar tus claves

El programa **no funciona sin un archivo `.env`**, porque de ahí saca la URL, la clave y el modelo. Por eso el `.env` real no se versiona; en su lugar se sube un `.env.ejemplo` que sirve de plantilla. El primer paso es copiarlo:

```bash
cp .env.ejemplo .env
```

Después abrís el `.env` y completás las claves. Cada proveedor te da la suya en su propio panel:

- **OpenAI** → creás la clave en `https://platform.openai.com/api-keys`. Es de pago: necesitás cargar saldo en *Billing* antes de que funcione.
- **Gemini (Google)** → la conseguís gratis en `https://aistudio.google.com/apikey`. Tiene un nivel gratuito generoso, ideal para probar en clase.
- **Groq** → clave gratuita en `https://console.groq.com/keys`, muy rápido para modelos abiertos.

Tu `.env` queda parecido a esto (poné la clave que conseguiste donde dice `sk-...`):

```
OPENAI_API_URL=https://api.openai.com/v1/chat/completions
OPENAI_API_KEY=sk-tu-clave-real-aca
OPENAI_MODEL=gpt-5.5

GEMINI_API_URL=https://generativelanguage.googleapis.com/v1beta/openai/chat/completions
GEMINI_API_KEY=tu-clave-de-gemini-aca
GEMINI_MODEL=gemini-2.5-flash
```

Recién con el `.env` completo podés ejecutar el programa. Sin argumentos usa OpenAI; pasándole el nombre elegís otro proveedor:

```bash
dotnet run 40.2-openai-httpclient.cs          # usa OPENAI_*
dotnet run 40.2-openai-httpclient.cs gemini   # usa GEMINI_*
```

> **Tratá tu clave como una contraseña.** No la pegues en chats, capturas de pantalla ni la subas a un repo. Si se te escapó, andá al panel del proveedor y revocala (regenerá una nueva): la vieja deja de servir al instante.

## El formato básico del pedido

El cuerpo del pedido es un JSON con una forma muy simple. Esta es la pieza central del apunte, así que vale la pena mirarla con calma:

```json
{
    "model": "gpt-5.5",
    "messages": [
        {
            "role": "user",
            "content": "traduce al inglés: hola mundo"
        }
    ],
    "temperature": 1
}
```

Tres campos importan:

- **`model`**: qué modelo querés usar. Lo decide el proveedor.
- **`messages`**: una lista de mensajes. Cada mensaje tiene un `role` y un `content`. Los roles son `system` (instrucciones generales de comportamiento), `user` (lo que dice el usuario) y `assistant` (lo que respondió el modelo en turnos anteriores). En el caso más simple mandamos un solo mensaje `user`.
- **`temperature`**: cuánta "creatividad" o aleatoriedad. Cerca de 0 = respuestas más determinísticas y repetibles; más alto = más variadas. Para extraer datos conviene bajarla; para generar texto creativo, subirla.

> **Lo justo y necesario.** El pedido más simple posible es solo `model` y `messages`; el resto de los campos son opcionales y la API usa un valor por defecto si no los mandás. Por eso el ejemplo manda lo mínimo: pide la completación y nada más.

### Armar el JSON a mano (y por qué hay que escapar)

El programa construye el JSON con un *raw string literal* interpolado (`$$"""..."""`):

```csharp
var json = $$"""
{
    "model": "{{Json(MODELO)}}",
    "messages": [
        {
            "role": "user",
            "content": "{{Json(prompt)}}"
        }
    ],
    "temperature": {{temperatura}}
}
""";
```

Fijate que el prompt pasa por una función `Json(...)`:

```csharp
static string Json(string texto) => JsonEncodedText.Encode(texto).ToString();
```

Esto es **imprescindible**. Si el prompt del usuario contiene comillas, saltos de línea o backslashes, y los metés crudos dentro del JSON, rompés el JSON y el pedido falla (o peor, abrís una puerta a inyección). `JsonEncodedText.Encode` convierte `él dijo "hola"` en `él dijo \"hola\"`. Es la versión chiquita y casera de lo que hace un serializador.

## El pedido HTTP

Con el JSON listo, el envío es directo:

```csharp
using var http = new HttpClient();
if (API_KEY is not null) {
    http.DefaultRequestHeaders.Authorization = new AuthenticationHeaderValue("Bearer", API_KEY);
}

using var contenido = new StringContent(json, Encoding.UTF8, "application/json");
using var respuesta = await http.PostAsync(URL, contenido);
```

Tres cosas que viajan en el pedido:

1. **El método y la URL**: un `POST` al endpoint de chat completions.
2. **El header `Authorization: Bearer <API_KEY>`**: así el servidor sabe quién sos y a quién cobrarle. Es el esquema de autenticación estándar de estas APIs.
3. **El cuerpo**: el JSON, con `Content-Type: application/json`.

## El formato básico de la respuesta

El servidor devuelve también un JSON. La parte que nos interesa está anidada acá:

```json
{
    "choices": [
        {
            "message": {
                "role": "assistant",
                "content": "translate to english: hello world"
            }
        }
    ]
}
```

`choices` es una lista porque podés pedir varias respuestas alternativas; nosotros tomamos la primera. El texto que generó el modelo está en `choices[0].message.content`. El código lo extrae navegando el árbol con `JsonNode`:

```csharp
return JsonNode.Parse(cuerpo)?["choices"]?[0]?["message"]?["content"]?.ToString() ?? "";
```

Y antes maneja el caso de error, que también vale la pena tener:

```csharp
if (!respuesta.IsSuccessStatusCode) {
    return $"Error HTTP {respuesta.StatusCode}:{respuesta.ReasonPhrase}\n{cuerpo}";
}
```

Cuando algo sale mal (clave inválida, modelo inexistente, sin saldo) el cuerpo del error suele explicar bastante bien qué pasó. No te lo guardes: mostralo.

## La idea central: una sola operación, muchos usos

Todo lo anterior se condensa en una función: `Completar(prompt)`. Recibe texto, se lo manda al modelo, devuelve texto. **Eso es todo lo que el modelo sabe hacer.** No "traduce", no "resume", no "programa". Sólo continúa el texto que le diste de la forma más plausible.

La magia no está en el modelo: está en **cómo redactás el prompt**. Cada función del programa es un prompt distinto envuelto en una firma de C# que le da nombre a la intención:

```csharp
async Task<string> Traducir(string texto, string idioma) {
    return await Completar($"traduce el siguiente texto al {idioma}: {texto}");
}

async Task<string> ExtraerNombre(string texto) {
    return await Completar($"extrae el nombre del siguiente texto en formato <apellido>, <nombre>: {texto}");
}

async Task<string> ExtraerFecha(string texto) {
    return await Completar($"Hoy es {DateTime.Now:yyyy-MM-dd}. Extrae la fecha relativa del siguiente texto: {texto}");
}

async Task<string> Resumir(string texto) {
    return await Completar($"resume el siguiente texto en una frase: {texto}");
}
```

Mirá lo que está pasando: programar contra el modelo es **escribir instrucciones en castellano y pegarles tu dato adelante o atrás**. La función `ExtraerFecha` es particularmente astuta: le inyecta la fecha de hoy (`DateTime.Now`) al prompt, porque el modelo no sabe qué día es. "El próximo lunes" sólo se puede resolver si le decís desde cuándo contar. Ese es un patrón clave: **vos aportás el contexto que el modelo no tiene; el modelo aporta el procesamiento del lenguaje.**

### De texto a artefactos

Dos funciones dan un paso más: en vez de devolver texto para leer, generan un archivo:

```csharp
async Task<string> Programar(string texto) {
    var resultado = await Completar($"Escribe un programa en c# que {texto}. Solo dame el codigo sin explicaciones.");
    File.WriteAllText("./40.0-programa.cs", resultado, Encoding.UTF8);
    return resultado;
}

async Task<string> PaginaWeb(string texto) {
    var resultado = await Completar($"Escribe una pagina web autocontenida en html que {texto}. Solo dame el codigo sin explicaciones.");
    File.WriteAllText("./40.0-pagina.html", resultado, Encoding.UTF8);
    return resultado;
}
```

El "Solo dame el codigo sin explicaciones" es importante: el modelo tiende a charlar ("¡Claro! Acá tenés tu programa..."), y eso ensucia un archivo que querés ejecutar. El prompt acota la salida.

### Consultar tus propios datos

La función más interesante combina el modelo con un dato local:

```csharp
async Task<string> Consultar(string texto) {
    var alumnos = File.ReadAllText("../alumnos/alumnos.md");

    return await Completar($"Actua como un asistente de programacion y responde a la siguiente pregunta: {texto}\n\nTen en cuenta esta informacion de los alumnos:\n{alumnos}");
}
```

Acá leés un archivo de tu disco, lo pegás dentro del prompt y le pedís al modelo que responda **a partir de ese contenido**. El modelo no tiene tus datos; vos se los das en el momento. Así podés preguntar "¿cuántos alumnos varones y mujeres hay?" o "¿a qué alumnos les falta el TP5?" sobre tu propia planilla. Esta es la semilla de lo que después se formaliza como **RAG** (Retrieval-Augmented Generation): traer datos relevantes y meterlos en el contexto antes de preguntar.

## Ideas para experimentar

Una vez que tenés `Completar`, agregar capacidades es agregar funciones de una línea. Algunas que valen la pena probar en clase:

```csharp
// Clasificar el sentimiento de un comentario
async Task<string> Sentimiento(string texto) =>
    await Completar($"Clasifica el sentimiento como POSITIVO, NEGATIVO o NEUTRO. Responde solo la palabra: {texto}");

// Corregir ortografía sin cambiar el contenido
async Task<string> Corregir(string texto) =>
    await Completar($"Corrige la ortografia y gramatica del siguiente texto, sin cambiar el sentido ni agregar nada: {texto}");

// Extraer datos estructurados como JSON (listo para deserializar)
async Task<string> ExtraerContacto(string texto) =>
    await Completar($"Extrae nombre, telefono y email del texto y responde SOLO un JSON con esas claves, sin markdown: {texto}");

// Generar preguntas de examen sobre un tema
async Task<string> Examen(string tema) =>
    await Completar($"Genera 5 preguntas de opcion multiple sobre {tema}, con 4 opciones cada una y la respuesta correcta marcada.");

// Explicar código que no entendés
async Task<string> Explicar(string codigo) =>
    await Completar($"Explica en castellano, paso a paso y para un principiante, que hace este codigo:\n{codigo}");

// Clasificar tickets de soporte en categorías fijas
async Task<string> Clasificar(string ticket) =>
    await Completar($"Clasifica este ticket en una de estas categorias: FACTURACION, TECNICO, VENTAS, OTRO. Responde solo la categoria:\n{ticket}");
```

El ejemplo de `ExtraerContacto` cierra un arco lindo: si le pedís al modelo que devuelva **JSON puro**, podés deserializar esa respuesta con `JsonSerializer` y conectarla directo a tu `Contacto` de la agenda. El modelo se vuelve un parser de texto libre a datos tipados. Ojo: como no es determinístico, conviene bajar la `temperature` y validar siempre lo que vuelve.

## Lo que hay que llevarse

El modelo expone **una sola operación: completar texto**. Todo lo demás — traducir, resumir, extraer, programar, clasificar, consultar tus datos — es esa operación más un prompt bien escrito. El "API compatible con OpenAI" es nada más que un formato JSON acordado para pedir esa completación por HTTP: `messages` adentro, `choices[0].message.content` de vuelta. Entendido el formato crudo, los SDK dejan de ser magia y pasan a ser comodidad: encapsulan exactamente este pedido y esta respuesta que acabás de armar a mano.
