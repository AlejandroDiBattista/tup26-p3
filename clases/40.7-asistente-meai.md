# Asistente MEAI
## Chatbot de consola con C#, OpenAI y Terminal.Gui

> [!IMPORTANT]
> La clave de acceso a la API es personal y secreta. No debe escribirse directamente en el código ni incorporarse al repositorio.

## Descripción general

Desarrollar un **chatbot de consola con interfaz gráfica**, construido con:

- **C# y .NET 10** — Lógica de la aplicación.
- **Microsoft.Extensions.AI** — Abstracción para interactuar con el modelo de lenguaje.
- **OpenAI** — Generación de las respuestas del asistente.
- **Terminal.Gui** — Interfaz de usuario dentro de la terminal.
- **Markdown** — Presentación del historial de la conversación.

El programa debe permitir que una persona escriba mensajes, enviarlos a un modelo de lenguaje y mostrar sus respuestas a medida que se generan. La conversación debe conservar el contexto de los mensajes anteriores para que el asistente pueda responder de forma coherente.

---

## Objetivos de aprendizaje

Al finalizar el ejercicio, el estudiante deberá poder:

- Configurar y utilizar un cliente de inteligencia artificial desde C#.
- Representar una conversación mediante mensajes con distintos roles.
- Enviar el historial completo al modelo para mantener el contexto.
- Procesar una respuesta mediante **streaming**.
- Actualizar una interfaz mientras se ejecuta una operación asincrónica.
- Gestionar errores durante la comunicación con el modelo.
- Proteger una clave de API mediante variables de entorno.

---

## Modelo de la conversación

La conversación debe estar formada por una lista ordenada de mensajes. Cada mensaje contiene un **rol** y un **texto**.

| Rol       | Propósito                                         |
|-----------|---------------------------------------------------|
| Sistema   | Define el comportamiento general del asistente.   |
| Usuario   | Representa cada consulta escrita por la persona.  |
| Asistente | Representa cada respuesta generada por el modelo. |

Al iniciar el programa, la lista debe contener un mensaje de sistema cargado desde el archivo `AGENTS.md` provisto junto con el scaffold. El prompt no debe estar escrito directamente en el código fuente.

El contenido de `AGENTS.md` debe indicar que el asistente:

- Ayuda con temas de programación.
- Responde en español de manera directa y técnica.
- Prioriza ejemplos en C# cuando no se especifica un lenguaje.
- Solicita solamente el contexto necesario cuando una consulta es ambigua.

Antes de solicitar cada respuesta se debe agregar el nuevo mensaje del usuario. Una vez finalizado el streaming, se debe agregar la respuesta completa del asistente. En las consultas siguientes se debe enviar la lista completa para conservar el contexto.

## Herramientas del asistente

El chatbot debe ofrecer al modelo las siguientes **tools** para trabajar con archivos:

| Tool               | Parámetros                   | Resultado                                             |
|--------------------|------------------------------|-------------------------------------------------------|
| `leer-archivo`     | Ruta del archivo             | Devuelve el contenido completo del archivo.           |
| `escribir-archivo` | Ruta del archivo y contenido | Crea o reemplaza el archivo y confirma la operación.  |
| `listar-archivos`  | Ruta de un directorio        | Devuelve los nombres de sus archivos y subdirectorios.|

Las tools deben implementarse como funciones de C# y registrarse en el cliente de inteligencia artificial. Cuando el modelo solicite una tool, la aplicación debe ejecutarla, devolverle el resultado y permitir que continúe elaborando su respuesta.

Todas las rutas deben resolverse dentro del directorio de trabajo de la aplicación. Se deben rechazar las operaciones que intenten acceder a una ubicación exterior. Si una ruta no existe, no es válida o no puede procesarse, la tool debe devolver un mensaje de error claro sin cerrar el chatbot.

## Funcionalidades requeridas

La aplicación debe implementar las siguientes funciones:

- **Enviar mensajes:** permitir escribir una consulta y enviarla con `Enter` o mediante un botón.
- **Validar la entrada:** ignorar mensajes vacíos o formados solamente por espacios.
- **Mostrar el historial:** identificar claramente los mensajes del usuario, del asistente y los errores.
- **Renderizar Markdown:** mostrar correctamente títulos, listas, énfasis y bloques de código.
- **Recibir por streaming:** mostrar la respuesta de manera progresiva, sin esperar a que el modelo termine de generarla.
- **Conservar el contexto:** incluir los intercambios anteriores en cada nueva solicitud.
- **Evitar envíos simultáneos:** deshabilitar la entrada y el botón mientras se procesa una respuesta.
- **Salir:** cerrar el programa únicamente con `Esc`.

Si la comunicación con el modelo falla, la aplicación debe mostrar el error dentro de la conversación, recuperar los controles de entrada y permitir volver a intentar.

---

## Diseño de la interfaz

La ventana debe ocupar toda la terminal y organizarse verticalmente en dos sectores:

1. **Conversación:** ocupa la mayor parte de la ventana y muestra el historial en formato Markdown. Debe permitir desplazarse con el teclado y el mouse.
2. **Entrada:** contiene un campo de texto de una sola línea y un botón **Enviar**.

Los mensajes deben presentarse con los siguientes encabezados:

- `👤 Vos` para los mensajes del usuario.
- `✦ Asistente` para las respuestas del modelo.
- `⚠ Error` para los errores.

La entrada y los bloques de código deben utilizar fondo blanco. El historial debe conservar la posición elegida por el usuario cuando se agrega contenido que no requiere seguimiento automático.

Mientras se recibe una respuesta, el viewport debe seguir progresivamente el nuevo contenido hasta que el encabezado `✦ Asistente` alcance el borde superior. Si el usuario desplaza manualmente el historial durante el streaming, el seguimiento automático debe detenerse hasta la próxima respuesta.

## Configuración y seguridad

La aplicación debe leer la clave desde la variable de entorno `OPENAI_API_KEY`. Puede utilizarse un archivo `.env` local para definirla:

```env
OPENAI_API_KEY=clave_personal
```

El archivo `.env` debe estar excluido del control de versiones. Si la variable no existe o está vacía, el programa debe finalizar con un mensaje que explique cómo configurarla.

El scaffold debe leer el contenido completo de `AGENTS.md` al iniciar y utilizarlo como único mensaje de sistema. Si el archivo no existe o está vacío, el programa debe finalizar con un mensaje de error claro.

El nombre del modelo debe declararse en un único lugar del programa para que pueda cambiarse sin modificar la lógica del chatbot.

---

## Organización del programa

El ejercicio puede resolverse en un único archivo ejecutable de C#, pero debe separar claramente estas responsabilidades:

- Configuración del cliente de inteligencia artificial.
- Construcción de la interfaz.
- Lectura y validación del mensaje del usuario.
- Administración del historial enviado al modelo.
- Procesamiento asincrónico del streaming.
- Actualización del historial visual y del viewport.
- Manejo del teclado y los errores.

La interfaz sólo puede modificarse desde el hilo principal de Terminal.Gui. Los fragmentos recibidos de manera asincrónica deben trasladarse a ese hilo antes de actualizar los controles.

---

## Criterios de aceptación

El trabajo se considera completo cuando:

- El programa inicia con una clave válida y muestra la interfaz sin errores.
- El mensaje de sistema se obtiene de `AGENTS.md` y no está escrito directamente en el código C#.
- La ausencia de `AGENTS.md`, o un archivo vacío, produce un mensaje de error claro.
- Un mensaje enviado con `Enter` aparece en el historial y recibe una respuesta progresiva.
- Una segunda pregunta puede hacer referencia a la respuesta anterior y el modelo conserva el contexto.
- El modelo puede usar `leer-archivo`, `escribir-archivo` y `listar-archivos`, y recibe el resultado de cada operación.
- Las tools no permiten acceder a rutas ubicadas fuera del directorio de trabajo.
- No es posible enviar otro mensaje mientras el asistente está respondiendo.
- Los bloques Markdown, incluido el código, se muestran correctamente.
- El auto-scroll respeta el límite y se pausa ante un desplazamiento manual.
- `Esc` cierra la aplicación y no existe otro comando de salida.
- Una falla de la API se informa sin cerrar inesperadamente la aplicación.
- La clave de API no aparece en el código ni en archivos versionados.
